# T-008 交接包：统一启动器与 strict 配置

## 1. 变更摘要
- `harness_lib.py launch [--strict] [--role task|plan] [--task T-xxx] [--root DIR] [--print-settings] -- <claude 参数>`；`harness launch` 为同一入口；`harness_lib.py sandbox-check`。
- strict：检查沙箱依赖（linux/wsl2 要 bwrap、socat、srt；wsl1/原生 Windows 拒绝）；在 `${XDG_STATE_HOME:-~/.local/state}/harness/<仓库>-<hash>/` 原子写入配置（600）并用 `--settings` 传入；清理环境里的凭证。
- 所有无人值守启动点（harness-loop 的任务/replan/groom、gate_github.start_run 的接续与 REQ）都走 strict。交互会话默认 standard（D-006）。

## 2. 对外契约
- 常量 `CONTROL_PATHS`、`CREDENTIAL_DIRS`、`CREDENTIAL_FILES`（harness_lib.py）是控制路径与凭证路径的唯一清单；T-009 的 control-diff 必须复用 `CONTROL_PATHS`。
- `launch_argv(args, root, strict, role, tid, env) -> (argv, env, problem)`、`strict_settings(root, role, tid) -> dict`、`sandbox_problem(platform) -> str`。
- 环境变量：`HARNESS_PLATFORM`（测试用覆盖）、`HARNESS_KEEP_ENV`、`HARNESS_STRICT=1`（由启动器设置）。
- 退出码：3 = 沙箱不可用 / 不是 git 仓库；2 = 参数错误。

## 3. 如何验证
- `bash pkg/tests/test_launch.sh`（185 项）、`bash pkg/scripts/test-harness.sh`（207 项）、`bash .harness/verify.sh`。
- 看实际配置：`python3 .claude/hooks/harness_lib.py launch --strict --root . --print-settings`。

## 4. 遗留问题
- strict 下 unlock 不生效，T-010 从答案库恢复。
- 规划运行能在主仓库新建新的顶层文件（不能改现有文件）。
- 真实沙箱拦截需在你的电脑上验收（B1）。
