# T-009 交接包：控制路径守门与沙箱内验证

## 变更摘要
- `harness_lib.py control-diff [<base>] <branch>`：列出命中控制路径（含嵌套 CLAUDE.md / .gitattributes、.gitmodules、.lfsconfig、.claude/**、.github/**、scripts/** 等）的文件；退出 1 = 命中，2 = git 错误（调用方一律当命中）。不分大小写与 Unicode 形式，识别符号链接 / 子模块替换父目录，非 UTF-8 文件名安全。
- 调度器在合并进整合分支前、推送 / 开 PR 前、作为下游基线前检查；分支取自 main 上任务卡的 `branch:`（必须 `task/<TID>-`），解析为 SHA 一次；合并后再对 `<pre>..<merged>` 检查。命中则任务 blocked 并在 main 写 `G-<TID>-ctl` 门卡。
- 整合验证在 `git archive` 流式导出的无 .git 副本里、经 srt（`HARNESS_SRT`）在沙箱中无凭证运行；网络白名单取自 main 的清单。控制面所有 git 调用关掉 hooks / fsmonitor / LFS 过滤器，推送从主仓库做，并在每次操作整合 worktree 前确认其 commondir。
- 教训不再自动写进 `.claude/rules/lessons.md`：sync-merged 写 `.harness/reports/lessons-proposed.md` 并开门卡，由你 `apply-gate` 采纳。
- strict 下 quick_check hook 不执行项目命令，改为提示 Claude 在沙箱里自己跑。

## 对外契约
- `control_diff(root, base, branch)`、`sandboxed_cmd(cmd, root)`、`harness_lib.py sandbox-run`、`task-branch`。
