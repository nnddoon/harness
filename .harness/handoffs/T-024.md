# T-024 交接包：控制面按基准任务卡检查改动范围（0.2.2）

## 变更摘要
- `control_diff(..., task=)`：分支改动的每个文件必须在**基准提交（main / scope base）上那张任务卡**的 `allowed_paths` 内，或是任务自己的记录文件（卡文件名以基准里那张为准）；否则计入「超出任务范围」（`control_diff_categories` 分 control / scope），走现有 ctl 门卡、不合并不推送。分支和 worktree 里的卡只是数据。
- 基准里同一任务号有多张卡 → 一律拦下（请人在 main 上删多余的卡）。基准卡没有 allowed_paths → 不做范围检查，doctor「## 任务范围」提醒。
- ctl 门卡批准只按快照内容放行（文件再改、mode 变、删除都重新命中），不再经 unlock 路径放行。
- protect_paths 规则 5 以主仓库卡为准；worktree 里改本任务卡的 allowed_paths / locked_paths / unlock / auto_ok / risk 被拒。
- 调度器与 new-task 的记账提交用临时索引，只提交记账路径；已有卡的范围字段改动、frontmatter 被破坏的卡、同一任务号新增 / 改名的卡一律扣留不提交并告警；有未答复 ctl 门卡的任务不重派；夜间模式用记录的任务基线（`--scope-base`）。

## 对外契约
- 扩大任务范围 = 人在 main 上改卡并提交，或批准 ctl 门卡（只放行快照内容）。任务自己写 §9 只是提议。
